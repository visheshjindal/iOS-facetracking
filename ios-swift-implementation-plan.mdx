## 1. Scope and decision rules

The experience runs locally. It helps a person position their face and gives live corrections. Acquisition means successful positioning, not identity verification, liveness detection, medical assessment, or certified image quality. Do not add recording, a shutter, saved photos, uploads, accounts, face recognition, depth requirements, audio capture, or a completion/results screen.

This specification was derived from the active tracking, positioning, lighting, rendering, session handling, and automated behavioral cases available during repository inspection. Historical descriptions of additional quality evaluators are not evidence of working features. The numbered requirements below define the complete scope for this implementation.

### Decisions and discrepancies

| ID | Decision | Status and instruction |
| --- | --- | --- |
| D01 | Alignment lasts 2,000 ms continuously | The written product requirement specifies two seconds; the inspected behavior uses 1,000 ms. Use **2,000 ms** in this plan and its tests. Record this as an intentional discrepancy resolution. |
| D02 | iPhone, portrait, front camera | Proposed deployment baseline: iOS 17 or later, Swift 6 language mode, a supported stable Xcode release. Confirm supported devices and toolchain in M0; these are implementation choices, not established product requirements. |
| D03 | SwiftUI interface with an AVFoundation preview | Use a single application target, plus unit-test and UI-test targets. Use ordinary initializer injection and Swift protocols. No dependency-injection framework is needed. |
| D04 | One primary face per analyzed frame | Preserve first usable detection behavior initially. Other faces do not block alignment and receive no overlay. Vision result order does not establish person identity. See R03 before declaring multi-person behavior stable. |
| D05 | Lighting is advisory | Bad or unknown lighting never prevents completion of an otherwise valid positioning hold. |
| D06 | Guidance filtering and drawing are independent | Preserve the 150 ms time-based filter used for positioning decisions. Draw from current measured geometry initially. Any later drawing interpolation must not change guidance inputs. |
| D07 | Native permission and Exit behavior | Denied access uses Settings; restricted access explains the restriction. Exit dismisses the capture route or returns to a landing screen. Never terminate the process programmatically. |
| D08 | Stale observation withdrawal | Add an explicit freshness event so a stalled detector cannot leave a green face frozen on screen. Withdraw the face after 300 ms without fresh usable results; show a failure after 5,000 ms without analysis results. This clarifies a stale-UI edge case. |
| D09 | Provisional lighting profile | Start with the numerical profile below as `ios-provisional-v1`. It requires iPhone calibration; copied thresholds are not evidence of accuracy. |

If discovery changes a decision, update this document, the versioned configuration, and the affected acceptance tests together. Do not silently replace a requirement with an easier implementation.

### Concurrency contract

1. All state transitions run synchronously on `MainActor`; never suspend partway through a transition.
2. Session setup, `beginConfiguration`/`commitConfiguration`, `startRunning`, and `stopRunning` execute in order on a dedicated serial camera queue. Do not run blocking capture work on `MainActor`.
3. A separate serial video-output queue performs Vision and luma work. One analysis is in flight at a time.
4. Send only small owned `Sendable` values from analysis to the store. Never send `CMSampleBuffer`, `CVPixelBuffer`, `VNFaceObservation`, or borrowed pixel pointers into observable state.
5. Use a newest-value mailbox for observations, with a capacity of one. Use a separate ordered, reliable path for authorization, failure, lifecycle, and start/stop completion events.
6. Each session command carries its session ID. Execute stop/start effects in one ordered command runner, not unrelated `Task` instances that can overtake each other.
7. Stopping invalidates the active generation before teardown. An in-progress synchronous Vision call may finish; discard its result and release its references.
8. An actor alone does not guarantee non-reentrant configuration across `await` points. Keep configuration atomic on its owner queue. Resolve Swift 6 delegate-isolation diagnostics deliberately in M2; do not silence them globally with unchecked conformance.

## 4. Models, units, and state contracts

Use `Double` for calculations and milliseconds from an injected monotonic time source for timing. Use `UInt64` for session IDs and `Int64` for elapsed milliseconds. Check overflow if an ID is incremented; a fresh process starts at zero. Dates and wall-clock changes must not affect timing.

```swift
struct FaceGeometry: Sendable, Equatable {
    let centerX: Double
    let centerY: Double
    let width: Double
    let height: Double
}

struct FacePose: Sendable, Equatable {
    let yawDegrees: Double
    let pitchDegrees: Double
    let rollDegrees: Double
}

struct FaceSample: Sendable, Equatable {
    let geometry: FaceGeometry
    let pose: FacePose?  // nil means unknown, never neutral
}

struct FrameObservation: Sendable {
    let sessionID: UInt64
    let geometryRevision: UInt64
    let capturedAtMS: Int64
    let face: FaceSample?
    let lighting: FaceLightingMetrics?
}
```

`FaceLightingMetrics` contains median, global trimmed mean, left/right/top/bottom trimmed means, shadow/highlight fractions, total count, and four regional counts. Store means on the documented 0–255 scale. Fractions use 0–1. Store no image references.

Coordinate convention: normalized mirrored viewport, top-left origin, x increasing rightward and y downward. Width and height are normalized separately. Geometry can extend outside the viewport during tracking; do not clamp a partially visible face into a falsely centered face. Require finite values, positive dimensions, and viewport intersection for a usable face. Missing pose still permits a measured outline in following mode, but never passes alignment or lighting eligibility.

`SessionState` owns authorization, scene activity, viewport/revision, session ID, desired running state, camera status, stage, current raw face, last accepted sample time, positioning history, lighting history, and current failure. Stage is `.aligning` or `.following`; tracking loss is derived from face absence while following, not a second acquisition stage.

`PositioningHistory` owns filtered geometry/pose, pose latch, hold anchor, stable-since time, and previous accepted observation time. `LightingHistory` owns active assessment/side, candidate assessment/side/start time, acceptable-evidence start time, and previous sample time. Clear histories on a new session.

Suggested events: authorizationChanged, sceneActive, sceneInactive, viewportChanged, retry, observation, freshnessExpired, cameraStarted, cameraFailed, cameraInterrupted, interruptionEnded, exit. Suggested effects: requestCameraStart(sessionID), requestCameraStop(sessionID), schedule/cancelWatchdog(sessionID), dismissCapture. Use typed failures, not raw framework error text.

Derive mask visibility, return-guide visibility, banner, badge state, and tracked oval from authoritative state. Do not store independently mutable copies of those flags.

### Session transition table

| Event / condition | State effect | Camera effect |
| --- | --- | --- |
| Authorized + active + positive viewport + no failure | Allocate next ID; clear histories; align | Start once |
| Duplicate eligible lifecycle event | No change | None |
| Inactive, dismissed, or access revoked | Clear face, histories, timers; no active attempt | Stop once |
| Real viewport or transform change | Increment geometry revision; discard old geometry; new alignment session | Ordered stop, then new start |
| Valid current observation with increasing timestamp | Update positioning, lighting, then primary guidance | None |
| Wrong ID/revision, stopped attempt, or non-increasing timestamp | Ignore entirely | None |
| Retry while eligible | Clear failure and histories; allocate next ID | Ordered stop then start |
| Current camera/detector failure | Clear face/history; show error | Stop |
| Interruption | Clear face/history; show paused-camera explanation | Suspend/stop on camera owner |
| Interruption ends, still eligible | Clear interruption; allocate new attempt | Start once |
| Freshness timeout | Clear face; reset continuity and lighting; keep following stage if acquired | Continue waiting for analysis |
| Five-second analysis stall | Detector-unavailable error | Stop; require retry |

A viewport change means a meaningful change to bounds/aspect/transform, not a subpixel layout jitter or a badge width animation. Snapshot viewport and transform revision with each frame. Camera and preview must use the same actual viewport.

## 5. Camera, permission, and frame pipeline

### Permission and capture setup

Include `NSCameraUsageDescription`: “Camera access helps position and follow your face on this device.” Request only camera permission. Use `AVCaptureDevice.authorizationStatus(for: .video)` and request access only for `.notDetermined`. Recheck after returning from Settings. Apple documents that the usage-description key is required and authorization is remembered. [Apple: capture authorization](https://developer.apple.com/documentation/avfoundation/requesting-authorization-to-capture-and-save-media)

For `.denied`, offer Open app settings and Exit. For `.restricted`, explain that device restrictions prevent access; do not repeatedly request authorization. For `.authorized`, wait for active scene and valid preview dimensions. If the front device is missing, show the front-camera error; do not silently switch cameras.

Select a front wide-angle camera using AVFoundation discovery. Start with a supported 640×480 or comparable analysis configuration and 30 fps preview, then profile. A chosen preset is a starting point, not a guaranteed delivered format. Record actual dimensions and frame duration in device evidence. Keep automatic exposure/white balance enabled initially; no torch, zoom gestures, beautification, or user exposure controls.

Use one `AVCaptureSession`, a video input, and an `AVCaptureVideoDataOutput`. Do not add microphone, photo, or movie outputs. Set the preview layer to `.resizeAspectFill`. Keep preview mirroring explicit; prefer unmirrored sample buffers and map into mirrored display coordinates once.

### Analysis sequence

1. On the serial output queue, verify active generation and frame geometry revision.
2. Capture monotonic arrival time immediately and retain sample presentation time separately for diagnostics. For initial implementation, observation time is delegate arrival time. It is not a guaranteed sensor-exposure timestamp; R05 requires validating latency under load.
3. Run a reused, serially owned `VNDetectFaceRectanglesRequest` with an explicitly chosen request revision and `CGImagePropertyOrientation` appropriate to the actual buffer.
4. Choose the first usable face observation. Do not assume the framework keeps a persistent identity or fixed ordering across frames.
5. Convert bounds and optional pose into owned Swift values. Vision pose angles are optional and expressed in radians; convert to degrees once. A missing angle makes the entire required pose unknown. [Apple: face observation](https://developer.apple.com/documentation/vision/vnfaceobservation), [Apple: yaw](https://developer.apple.com/documentation/vision/vnfaceobservation/yaw)
6. Sample the Y plane from this same frame, map sample locations into the same viewport, and calculate face lighting statistics.
7. If analysis finishes more than 300 ms after arrival, publish an unavailable face/lighting observation, never an old usable face. If a result becomes stale in the delivery mailbox, reject its usable payload there too.
8. Publish the small observation and release all sample-buffer references. A successful request with no faces is a normal observation; a thrown request error is a detector failure.

Use `alwaysDiscardsLateVideoFrames = true`. Intentional analysis throttling and dropped output frames are not proof that camera hardware has stopped. Track `captureOutput(_:didDrop:from:)` separately if needed for diagnostics. Apple's frame-drop guidance recommends bounded delivery and reducing workload when processing cannot keep pace. [Apple: TN2445](https://developer.apple.com/library/archive/technotes/tn2445/_index.html)

Start the 5,000 ms watchdog when an attempt starts. Check every 250 ms. Update last-result arrival for successful face and no-face results; never let a nil-face result be mistaken for a stalled detector. Separately expire visible face data once its accepted timestamp is older than 300 ms. Inject timers and clocks for tests; cancel both on stop. A freshness event must carry the expected last-sample timestamp so it cannot erase a newer observation.

## 6. Geometry and rendering specification

### Viewport and target oval

Define `W` and `H` as the actual preview container size in points after the chosen safe-area layout. The preview, guide, overlay, and guidance measurements all use this rectangle. Keep the top banner overlaid; changing its height must not resize the camera viewport.

```text
ovalWidthPoints  = min(0.72 × W, (0.50 × H) / 1.35)
ovalHeightPoints = 1.35 × ovalWidthPoints
targetWidth      = ovalWidthPoints / W
targetHeight     = ovalHeightPoints / H
targetCenter     = (0.5, 0.5)
```

No target exists when either viewport dimension is non-positive. Use these same calculated dimensions for initial cutout, fixed return guide, and positioning thresholds.

### Image-to-preview transform

Maintain named spaces: raw buffer pixels, oriented unmirrored image pixels, Vision normalized coordinates, preview points, and preview normalized coordinates. Write conversions as small tested functions and store a frame-specific transform snapshot.

Vision normalized bounds use a lower-left origin. Convert to oriented top-left image coordinates before crop/mirror operations. [Apple: boundingBox](https://developer.apple.com/documentation/vision/vndetectedobjectobservation/boundingbox)

For Vision rectangle `(x, y, w, h)` in an oriented image of size `Iw × Ih`:

```text
imageLeft = x × Iw
imageTop  = (1 - y - h) × Ih
imageWidth = w × Iw
imageHeight = h × Ih

scale = max(W / Iw, H / Ih)
offsetX = (W - Iw × scale) / 2
offsetY = (H - Ih × scale) / 2

previewX = imageX × scale + offsetX
previewY = imageY × scale + offsetY
mirroredPreviewX = W - previewX
normalizedX = mirroredPreviewX / W
normalizedY = previewY / H
```

Map all four corners and rebuild an axis-aligned bounding rectangle. Apply orientation first; mirrored rectangle left is `W - unmirroredRight`, not `W - unmirroredLeft`. The formulas assume the oriented dimensions describe the actual displayed image, including its clean aperture. Confirm clean-aperture and preview-layer conversion behavior in R02.

Map luma sample centers from raw buffer coordinates through the same rotation/crop/mirror transform. Do not transform luma as though it were already Vision-normalized. Mirror exactly once. Preview mirroring must not implicitly mirror already-mirrored observations again.

For portrait rotation, use supported `videoRotationAngle` APIs and check support before setting a value. A fixed interface orientation does not guarantee upright delivered pixels. Do not both physically rotate the data output and describe the original orientation to Vision. [Apple: rotation support](https://developer.apple.com/documentation/avfoundation/avcaptureconnection/isvideorotationanglesupported(_:))

### Visual contract

| Element | Required appearance |
| --- | --- |
| Initial mask | White opaque rectangle with transparent oval cutout using an even-odd path. No darkened cutout or face-shaped asset. |
| Acquisition transition | White mask opacity goes from 1 to 0 over 450 ms. Following state changes immediately; animation does not delay logic. Respect Reduce Motion. |
| Tracked oval | Green `#00FF87`, 5-point stroke; matches current raw face box. Visible only after acquisition and while face geometry is fresh. |
| Return guide | Always visible in following mode, including while a face is visible. Centered target oval, white at 0.82 opacity, 3-point stroke. |
| Guide eye details | Eye centers at target center x ± 0.18 oval widths; y at center minus 0.11 oval heights. Eye ellipses 0.13 oval widths × 0.035 oval heights; 2-point strokes and 2-point center dots. |
| Banner | Top full-width overlay with 24-point padding. White/black text during alignment; black at 0.70 opacity with white text during following. Allow wrapping. |
| Lighting badge | Top trailing, 16-point trailing margin, 8-point top gap below banner; minimum 40-point visual height, 22-point icon. Keep within safe bounds at large text sizes. |
| Badge colors | Unknown: black at 0.68 opacity with white; acceptable: `#128A52` with white; warning: `#FFB020` with black. |

Draw with SwiftUI `Shape`/`Canvas` or lightweight shape layers. The return guide is a fixed positioning illustration, not detected eye landmarks. Do not rotate it with the face. Keep the preview host stable through text and badge changes.

## 7. Positioning and following algorithms

### Versioned constants

| Parameter | Value | Meaning |
| --- | --- | --- |
| Hold | 2,000 ms | Continuous eligible acquisition |
| Maximum sample gap | 300 ms inclusive | 300 continues; 301 resets |
| Guidance EMA time constant | 150 ms | Applied to geometry and known pose |
| Center tolerance | 0.10 × target width/height | Separate axis tolerances |
| Minimum face scale | 0.65 × target dimensions | Both dimensions must meet minimum |
| Maximum face scale | 0.95 × target dimensions | Neither dimension may exceed maximum |
| Pose entry limits | yaw 10°, pitch 15°, roll 8° | Absolute values, inclusive |
| Pose exit limits | yaw 13°, pitch 20°, roll 11° | Used while pose-valid latch is set |
| Anchor position delta | 0.025 | Absolute normalized x or y delta |
| Anchor size delta | 0.025 | Absolute normalized width or height delta |
| Anchor angle delta | 5° | Absolute delta of each angle |

All these are initial heuristic settings. Geometry and pose thresholds need confirmation with Vision output; do not claim they represent physical distances.

### Per-observation procedure

1. Reject obsolete session/revision and non-increasing timestamps before changing any history.
2. Validate face geometry and pose independently. Missing geometry means no face; missing pose means unknown posture.
3. If continuous, filter each known scalar with `alpha = 1 - exp(-deltaMS / 150)` and `filtered = previous + alpha × (current - previous)`. Reset the filter after face absence or a gap over 300 ms. Never smooth a missing angle into a valid one.
4. Update pose latch: if previously false, use entry limits; if true, use exit limits. Unknown pose clears the latch. On a new session clear it. Preserve its prior value across a timestamp gap only when the current complete pose remains within the exit band; the hold itself still resets. This matches the existing hysteresis behavior.
5. Resolve positioning hint with the priority below.
6. While aligning, a hint other than hold-still clears hold time and anchor. If eligible but continuity broke, start a new hold at this observation.
7. Otherwise compare filtered face with the fixed hold-start anchor. A delta strictly greater than any anchor limit restarts the hold at the current sample and replaces the anchor. Do not compare only adjacent samples: slow drift must also reset.
8. If eligible elapsed time reaches 2,000 ms, set stage to following. A timer alone cannot acquire; acquisition requires a fresh eligible observation at or beyond the threshold.
9. While following, compute corrective hints but never start another acquisition hold. Loss preserves the following stage.

### Exact hint priority

| Priority | Condition | Alignment hint | Following hint |
| --- | --- | --- | --- |
| 1 | No usable face / no target | Place face | Tracking lost |
| 2 | Horizontal center outside tolerance | Center face | Face left of target: Move right; face right: Move left |
| 3 | Vertical center outside tolerance | Center face | Face above target: Move down; face below: Move up |
| 4 | Width OR height greater than maximum | Farther | Farther |
| 5 | Width OR height less than minimum | Closer | Closer |
| 6 | Pose unknown or outside applicable limits | Look straight | Look straight |
| 7 | All positioning checks pass | Hold still | Following |

Use strict inequality for out-of-tolerance center/size and movement; equality passes. Check too-large before too-small when different dimensions disagree. Horizontal correction precedes vertical correction. Screen movement instructions use the mirrored preview frame; validate that following the instruction moves the visible face toward center.

Lighting does not participate in the hold predicate. The hold can finish while the banner contains lighting advice. No progress bar or countdown is required; if internal progress is exposed for testing, derive `clamp(elapsed / 2000, 0...1)` and do not create another timer authority.

## 8. Lighting measurement and classification

### Pixel sampling

Prefer a supported 8-bit bi-planar YCbCr output. Inspect available pixel formats and use a supported full-range format where practical. Avoid converting every frame to BGRA or `UIImage` just to read brightness; Apple describes the memory and conversion costs of format choices. [Apple: TN3121](https://developer.apple.com/documentation/technotes/tn3121-selecting-a-pixel-format-for-an-avcapturevideodataoutput)

Lock the pixel buffer read-only while sampling and unlock with `defer`. For plane zero, use its actual width, height, and bytes-per-row. Never assume bytes-per-row equals width. Restrict this sampler to the explicitly supported 8-bit formats; unsupported layout yields unavailable lighting.

Copy a 64×64 grid, at most 4,096 samples. For column `c` and row `r`, sample pixel indices `floor((c + 0.5) × sourceWidth / 64)` and `floor((r + 0.5) × sourceHeight / 64)`, clamped to valid bounds. For geometry mapping, use the corresponding continuous cell-center coordinates. Keep any reusable arrays local to the serial analyzer; do not recycle storage still held by an asynchronous consumer.

Define canonical 0–255 luma before thresholding. For supported full-range 8-bit Y use the byte directly. For supported 8-bit video-range Y, provisionally normalize `clamp((Y - 16) × 255 / 219, 0...255)` and round to the nearest integer histogram bin. This is a range conversion, not a colorimetric or skin-exposure calibration. Confirm format semantics and compare both formats in R04.

For each transformed sample, calculate coordinates within the raw current face box:

```text
u = (sampleX - faceLeft) / faceWidth
v = (sampleY - faceTop) / faceHeight
inside = ((u - 0.5) / 0.40)² + ((v - 0.5) / 0.38)² <= 1
```

Include only inner-ellipse samples. Split left/right at `u = 0.5` and top/bottom at `v = 0.5`; equality goes into right/bottom. These are mirrored viewport regions. The darker screen-left region maps to the user-left lighting instruction only after physical verification of the mirror convention.

Build five 256-bin histograms: all, left, right, top, bottom. Require at least 96 total samples and 32 samples in each region. Derive:

- Median: average the values at zero-based ranks `(count - 1) / 2` and `count / 2`, using integer division for ranks.
- Trimmed mean: remove `floor(count / 10)` samples from each end, then average the remaining samples. Trim by rank, including partial histogram buckets.
- Shadow fraction: number of values at or below 24 divided by total.
- Highlight fraction: number of values at or above 235 divided by total.

Reject non-finite/out-of-range values, inconsistent regional counts, empty regions, non-positive face dimensions, and fractions whose sum exceeds one. Left plus right count and top plus bottom count must each equal total. Missing transform, missing face, insufficient samples, unknown pose, or failed pose eligibility makes lighting unknown. Never reuse a previous frame's valid metrics.

### Classification thresholds and precedence

| Check | Enter condition | Condition while its warning is active |
| --- | --- | --- |
| Dark | median below 55 OR shadow fraction at least 0.25 | median below 65 OR shadow fraction at least 0.20 |
| Bright | median above 205 OR highlight fraction at least 0.20 | median above 195 OR highlight fraction at least 0.15 |
| Uneven, either axis | difference at least 28 AND darker/brighter ratio at most 0.75 | difference greater than 20 AND ratio below 0.82 |

For ratio, use one if brighter mean is zero. Evaluate dark and bright first. While high-contrast is active, apply both exposure exit bands. If both are true, classify high-contrast; if only dark, too-dark; if only bright, too-bright. Otherwise test horizontal and vertical imbalance. Any vertical imbalance, including both axes, means uneven with no side. Horizontal-only imbalance means uneven with the darker side. Otherwise classify acceptable.

While any uneven warning is active, use the uneven exit thresholds for both axes. A side change is a new candidate, not an immediate string change. Vertical or mixed exposure advice always asks for soft, even light; it must not invent a left/right correction.

### Temporal state algorithm

1. Ignore non-increasing timestamps.
2. Missing/invalid eligible metrics or a gap greater than 300 ms resets to unknown and clears all candidates. For a gap, discard that sample for classification; start settling on the next continuous valid sample.
3. Classify using the active warning's hysteresis bands.
4. If classification and side match the active state, clear any pending candidate and retain the active state.
5. Otherwise start or continue a candidate keyed by assessment **and** side. Candidate changes restart its timer.
6. Commit warnings after at least 400 ms; commit acceptable after at least 700 ms. Before commit keep the prior active state.
7. When acceptable commits, store the candidate start as acceptable-evidence start. Compact the badge after at least 1,500 ms from that start, not 1,500 ms after the 700 ms commit. Compute from fresh observations; wall-clock passage without measurements does not establish acceptable evidence.
8. An invalid sample immediately withdraws acceptable status. A brief uncommitted warning candidate does not replace the active acceptable assessment; on warning commit, expand again when positioning permits.

### Primary guidance and badge state

Positioning hints other than hold-still/following always win the primary banner. Otherwise an active lighting warning replaces the hold/following message. Unknown or acceptable lighting leaves the positioning message in place.

Show the badge only when there is a fresh face and no blocking camera failure. It is expanded only when positioning is hold-still/following, lighting is known, and either the warning is active or acceptable evidence has not reached the compact threshold. During position correction or unknown lighting, keep an icon with its full accessible label. When the face is absent, hide the badge. A compact badge is not a tappable control unless a later requirement adds an action.

## 10. Performance, energy, and reliability gotchas

These are **proposed engineering targets**, not measured guarantees. Record actual results before accepting them.

| Area | Initial target / safeguard | Verification |
| --- | --- | --- |
| Preview | Request 30 fps when supported; smooth visible preview during analysis | Instruments and device observation |
| Analysis | Start at approximately 15 analyzed frames/s if 30 is too costly; p95 analysis under 100 ms on oldest supported device | Signposts around detection, sampling, mapping |
| Freshness | Never display a face result more than 300 ms old | Inject delayed detector + device stress |
| Buffering | One in-flight frame; at most one small pending observation | Counters and memory graph |
| UI | No blocking camera calls, image conversion, or Vision work on main actor | Time Profiler and responsiveness instrument |
| Memory | No monotonic retained-buffer growth after warm-up over a 10-minute run | Allocations and memory graph |
| Stop/start | No overlapping active camera generations across 50 lifecycle/retry cycles | Automated fake service + device cycles |
| Lighting sampling | No RGB conversion, fixed 4,096 samples, reusable histogram workspace | Allocation/profile inspection |
| Thermal | Under sustained pressure, reduce analysis cadence/resolution; maintain freshness semantics | 10-minute baseline and stressed run |

Important implementation traps:

- `Task {}` created from a main-actor context can inherit that isolation. It is not proof that expensive work moved off the UI thread.
- Unbounded asynchronous frame tasks retain camera buffers and can exhaust the capture pool. Perform synchronous Vision work on the serial analysis queue and return promptly.
- A preview session can report running while no useful analysis arrives. Monitor actual results and handle AVFoundation interruption/runtime-error notifications.
- A latest-value mailbox limits memory but does not make the last observation fresh. Check age on consumption and expire visible state independently.
- Variable frame rate requires elapsed-time smoothing and persistence; frame counts are unsuitable for two-second holds.
- A 150 ms guidance filter can hide brief motion. Keep the anchor comparison, and validate slow drift and fast motion on devices before modifying the filter.
- A 64×64 grid can provide too few samples for a small/cropped face. Return unknown rather than loosening count requirements silently.
- Automatic exposure, HDR, output range, front-camera processing, and mask-generated screen light can shift luma readings. Keep format/profile information in aggregate diagnostics.
- Repeated layout callbacks can cause camera restart loops. Deduplicate stable viewport values and keep badge layout independent of the preview.
- Permission dialogs and Control Center change scene activity. Never treat inactive as proof of permanent denial.
- A failed request must not be reclassified as a valid no-face result. Users need a retry path for detector failure.
- Do not update the whole screen at display refresh rate merely to animate a box. Publish observations at analysis cadence and keep any drawing interpolation local.
- Prevent callbacks from retaining dismissed stores/routes. Cancel tasks and observers explicitly; validate deallocation after leaving the screen.
