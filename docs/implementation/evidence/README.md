# Verification evidence

Store concise Markdown records here; never store participant frames, crops, landmarks, or identifying face data. Synthetic fixtures belong in test resources with provenance.

Each record needs requirement/test/research IDs, date, build identifier, device model/OS, Xcode/Swift, Vision request/revision, delivered dimensions/pixel format/range, profile version, setup, procedure, expected and observed result, pass/fail/NOT RUN, limitations, and reviewer role. Use anonymous aggregate results where appropriate.

If hardware, signing, Instruments, participants, or a human reviewer is unavailable, write a reproducible procedure and mark it NOT RUN. Simulator results never close physical-camera gates. Keep calibration tuning and held-out evaluation separate; R07 tolerances must be selected before evaluating the held-out set.
