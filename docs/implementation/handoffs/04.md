## Changes and contracts

- Xcode MCP was enabled and approved. `XcodeListWorkspaces` found the open `facetracking.xcodeproj`. The active destination was switched from the connected physical iPhone to the eligible `iPhone 18 Pro` iOS 27.0 simulator for deterministic automated tests, then restored to `Vishesh’s iPhone` after verification.
- Added `facetracking/Camera/FrameCoordinateMapper.swift` with explicit `Sendable` coordinate values: `CoordinateSize`, `RawPixelRect`, `RawBufferPoint`, `VisionNormalizedRect`, and `NormalizedViewportPoint`.
- Added immutable `FrameTransformSnapshot`. It records geometry revision, raw buffer dimensions, oriented image dimensions, raw-to-oriented quarter-turn, Vision orientation policy, clean-aperture policy, viewport points, portrait interface orientation, and explicit preview mirroring.
- `FrameCoordinateMapper.mapVisionBounds(_:using:)` accepts only already-oriented Vision lower-left normalized rectangles. It converts to oriented top-left pixels, maps all four corners through centered aspect fill and one optional mirror, rebuilds an axis-aligned box, normalizes by viewport width/height, preserves partly clipped geometry, and rejects completely outside geometry.
- `FrameCoordinateMapper.mapRawSamplePoint(_:using:)` is the separate plan-06 entry point for raw top-left pixel coordinates and luma cell centers. It subtracts clean-aperture origin, applies one 0/90/180/270-degree raw quarter-turn, then uses the same aspect-fill/mirror transform as face geometry.
- Invalid, missing, non-finite, zero-sized, aperture-out-of-buffer, oriented-size-inconsistent, and double-rotation policy snapshots return unavailable values. There is no identity fallback.
- Orientation contract for plan 05: Vision bounds passed to the mapper are already oriented. For plan-03 output that is proven physically upright, use `.degrees0` with `.bufferAlreadyOriented`. Otherwise use the measured raw quarter-turn with `.visionAppliesSnapshotRotation`. Never physically rotate and also tell Vision to rotate.
- Pinned-SDK/API reconciliation used official Apple contracts: `AVCaptureVideoDataOutput` physically rotates buffers when its connection's `videoRotationAngle` is applied; Core Media exposes top-left clean aperture through `CMFormatDescription.cleanAperture(originIsAtTopLeft: true)`; preview-layer metadata conversion already accounts for layer size and `videoGravity` but uses metadata-output top-left normalized coordinates, so it is not substituted for the explicitly tested Vision lower-left path. Plan 05 must read the delivered format description per frame and snapshot those values.

- Updated `Camera/AGENTS.md`, `Tracking/AGENTS.md`, and `facetrackingTests/AGENTS.md` with named spaces, entry-point ownership, frame policy, and asymmetric-fixture conventions.
