## Changes and contracts

- Xcode MCP was already enabled and approved. `XcodeListWorkspaces` found the open `facetracking.xcodeproj`; no configuration change was necessary.
- Added `CameraAuthorizing` and `SystemCameraAuthorization`. Status maps to the plan-02 `CameraAuthorization` value type; access is requested only from the Grant action while `notDetermined`, with duplicate in-flight requests suppressed.
- Added `CameraSessionControlling`, `CameraSessionService`, `CameraServiceEvent`, `CameraSelection`, and `CameraPreviewSession`. One `AVCaptureSession` uses front wide-angle video input and one `AVCaptureVideoDataOutput`; frames are discarded until plan 05. There are no audio/photo/movie outputs or rear-camera fallback.
- Session configuration/start/stop is confined to `xim.facetracking.camera.session`; video delivery uses `xim.facetracking.camera.output`. Reducer effects call the service in array order and the service's serial queue preserves stop-before-start completion order. IDs cross queues as owned values and obsolete callbacks are rejected by `SessionTransition`.
- Configuration uses one balanced `beginConfiguration`/`commitConfiguration` transaction. If any later setup or device-lock step fails after adding an input/output, both additions and the sample-buffer delegate are rolled back before retry, preventing partial-session accumulation.
- `CameraPreviewSession` is the narrow `@unchecked Sendable` interoperability wrapper. It exposes an immutable session reference: only the camera queue mutates configuration/running state, while MainActor attaches it to the preview layer. `CameraPreview` uses `resizeAspectFill`, portrait 90-degree rotation when supported, and explicit mirroring.
- Physical launch exposed AVFoundation's mirroring precondition: manual `isVideoMirrored` assignment is invalid while `automaticallyAdjustsVideoMirroring` is enabled. Both preview and data-output connections now disable automatic adjustment immediately before applying their explicit mirrored/unmirrored policy.
- Physical preview feedback also showed the fixed 90-degree preview assumption could render landscape. `PreviewView` now creates `AVCaptureDevice.RotationCoordinator` after the front-camera input becomes available and applies `videoRotationAngleForHorizonLevelPreview`; the data-output policy remains separately recorded for plan 04.
- Output policy for plan 04: preview mirrored once; video-data connection explicitly unmirrored; both request 90-degree portrait rotation when supported. `CameraSelection` records active-format width/height, requested 30 fps, rotation, and mirror policy. Delivered dimensions/rate remain a physical-device measurement.
- Added `CaptureDependencies`, injected monotonic clock and native Settings opener, stable `CaptureRoute`/`CaptureStore`, minimal `CaptureViewState`, and localized permission/failure UI. `CaptureStore` is `@MainActor @Observable` with `private(set)` view state; dependencies and reducer state are observation-ignored. `CaptureRoute` owns it with `@State`.
- Route/scene/viewport/auth/service/retry/exit events flow through the plan-02 reducer. Watchdog/freshness effects are intentionally ignored until plan 05 supplies analysis results, preventing a false five-second detector failure.
- Replaced the foundation capture placeholder while preserving `facetrackingApp` identity and the landing/full-screen dismissal flow.
- Added `CameraPreviewLifecycleTests` covering authorization, injected Settings/Exit, eligibility, command ordering, stale callbacks, interruption behavior, 50 lifecycle cycles, and weak release.
- Added `facetracking/Camera/AGENTS.md`, `facetracking/CaptureUI/AGENTS.md`, and `facetracking/App/AGENTS.md`; updated test guidance and synchronized-group exclusions so Markdown is not bundled.
